给自建后端的开发者
English edition

把你的后端接到 CellPilot

你的后端驱动 4G 模块、保存短信和通话记录；CellPilot App 负责手机上的一切；需要叫醒手机时，推送经 CellPilot 中转送到 Apple，内容是封装的，中转读不到。先读“入门”，再按类型查每个接口。

入门

先读这一组：你和 CellPilot 各做什么、按什么顺序接入、所有接口共用的约定。这一页从本仓库的规范 spec/device-api.md 派生，不另加任何规则；两者不一致时以规范为准。写着“参考后端”的，是参考后端在规则之内的做法，不是你必须照做的。

谁做什么

App 只认 Device API，不关心你用什么硬件、什么语言、跑在哪里。实现了 API 的后端，App 就能用。

合法用途。 CellPilot 仅为合法用途而制作。我们遵守法律法规，不认可、不支持、也不协助任何违法活动。如果你发现问题——滥用，或产品、文档中有任何与法律法规相抵触的内容——请立即通过 abuse@cellpilot.dev 告诉我们。我们会配合有关部门并予以整改，必要时变更、限制或关闭相关功能或服务。CellPilot 面向一个人用自己的 SIM 卡、在自己的设备上使用；它不能替代电话服务，不能依赖它拨打紧急电话（紧急呼叫从模块所在地发出，可能接到错误的急救中心）。

你来做

  • 驱动你的模块或 SIM：收发短信、打接电话、读信号。
  • 实现 Device API 的核心接口，再按能力声明可选特性。
  • 保存数据：短信、通话记录，以及可选的联系人、留言。
  • 决定 App 怎么连到你：局域网、虚拟组网（如 Tailscale、WireGuard）或内网穿透都行。

CellPilot 提供

  • iOS App：界面、CallKit 来电、通话音频、通知。
  • 这份规范、一致性检查工具 api-check、中转替身 test-relay 和最小后端 mock-backend。
  • 推送中转 push.cellpilot.dev：把你加密好的推送送到手机，你不需要 Apple 开发者账号。

接入路线

按这个顺序做，每一步都能单独验证。最少只需要第 2、3 步，App 就能用你的后端收发短信、打电话。

  1. （可选）先看一个能用的最小后端。 本仓库的 tools/mock-backend.mjs 只实现核心接口，一个文件、没有依赖，短信和通话都是模拟的。跑起来，在 App 配对页点“输入地址”连上它。没有就跳过这一步。
  2. 实现核心接口。 发现、配对、客户端记录、状态、通话、通话记录、短信、事件流。核心接口清单可以逐项打勾。
  3. 自检。 用 tools/api-check.mjs：默认只读，不拨号、不发短信，按设计不做任何改动，可以对插着真 SIM 卡的后端运行；每个响应和事件帧都逐字段对照 openapi.json 和 events.schema.json。模拟设备的后端再加上写入和模拟钩子的检查，见自检工具。
  4. 按能力声明可选特性。 做到哪个声明哪个；没声明的，App 不显示对应的按钮，也不会请求。
  5. 接推送。 经 CellPilot 中转，登记由 App 牵线，见推送一组。

基本约定

所有接口都在 /v1 下，下面这些约定对每个接口都成立。

方面约定
格式双向 JSON，字段名 camelCase。你的响应带 Content-Type: application/json; charset=utf-8。请求体一律按 JSON 解析，不必检查请求的 Content-Type：没有请求体当作 {}；不是合法 JSON，或是 JSON 但不是对象（数组、字符串、null），回 400 invalid_request（不带 details）；不认识的字段忽略。请求体超过你自定的大小可以回 413 invalid_request（参考后端：8 MB）。成功的响应都是 JSON 对象：集合放在有名字的键下（{ "messages": [...] }），单个资源就是对象本身，删除返回 {}。
字段对象里列出的字段总是带上：不知道、不适用、或属于你没声明的特性（没有 places 时的 place，没有 contacts 时的 name、contactId）都写 null，不要省略；数组为空写 []。只有下面“可选字段”表里的和标着“可选”的可以不带。
路由不存在的路径，以及存在的路径用了它不接受的方法，都回 404 not_found（在鉴权之后），没有 405。
时间与时长UTC 的 ISO 8601，字段名以 At 结尾："2026-09-25T08:14:03.120Z"。时长带单位：durationS。
id短信、通话记录等的 id 是正整数，新记录的 id 比旧的大。路径里的 id 不是非负整数时回 400 invalid_request，details.field 为 "id"。
鉴权除 GET /v1、GET /v1/ping、POST /v1/pair（接口标题旁标着“无需鉴权”）外都带 token：Authorization: Bearer <token>，端点设了 tokenHeader 时改为 X-CellPilot-Token: <token>，两种都要认（两个都带时读 X-CellPilot-Token，另一个是代理的）。只存 token 的哈希。
• 没带 token，或你从没发过这个 token：401 unauthorized。
• 你撤销的、或手机自己解除配对的 token：410 signed_out。要认得出它，所以撤销后保留它的哈希。
• 同一个 uid 重新配对后，旧 token 就成了“不认识的”，回 401。
App 对一个原本能用的 token 收到 401 或 410，处理都一样：丢掉 token 和缓存，回到配对页。
分页?beforeId=<id>&limit=<n>：按 id 从大到小排（新的在前），只返回 id 小于 beforeId 的。limit 默认 100，超出范围不报错，夹到 1–500 之间。beforeId 或 limit 不是数字时当作没带。返回少于 limit 条就是最后一页。这是通用规则；接口自己写了默认值和上限的（搜索 50 / 200、日志 200 / 1000），以接口为准。
语言你生成的给人看的文字（错误的 message、失败原因、归属地、告警、日志）用读者的语言。只有 en 和 zh：以 zh 开头的（如 zh-Hans）当 zh，其他一律当 en。号码、用户输入的内容、名字不翻译。
• HTTP 请求：用 X-Lang 请求头（App 每个请求都带）；没带时用这台手机记录里的 lang（配对或 PATCH /v1/client 时给的）；都没有就用 en。
• 事件流：每个连接用它那台手机记录里的 lang。语言不同的手机收到的同一个事件，文字各用各的语言。
• 几台手机共用的记录（短信的 error、通话记录的 endReason）：存原因本身，读取时按读者的语言生成文字，不要存一句译好的话。

所有错误都是同一个信封。HTTP 状态和 error.code 的对应见下表。App 按 code 处理，message 直接显示给人看，用读者的语言。details 可选，放在 error 里面；字段不对时 details.field 写字段名，嵌套字段用点连起来（"voicemail.answerAfterS"）。

HTTPcode什么时候
400invalid_request字段缺失或格式不对，details.field 指出是哪个；请求体不是 JSON 对象（这时没有 details）。
401unauthorized没有 token，或不是后端认识的 token；配对码不对。
403forbiddentoken 有效但不能做这件事。
404not_found没有这个资源或路由。
404feature_unavailable路由属于你没声明的特性。
409conflict和当前状态不符：没有来电时接听、已有通话时拨号。
413invalid_request请求体超过你接受的大小。
500internal其他问题，包括模块拒绝了命令（见通话动作的错误）。
502upstream_failed只用于 POST /v1/push/enrol：中转拒绝了登记或连不上。
410signed_out客户端被解除配对或撤销。
429rate_limited同一来源失败太多次，带 Retry-After（秒）。
503device_unavailable模块没接或没就绪。

先鉴权，再找路由：不带 token 请求一个不存在的路径，回 401 而不是 404。

号码与会话

带国家码的按那个国家或地区的规则分析；没有国家码的按 SIM 卡归属国家或地区的规则分析；都分析不出来就是一串数字。

三条规则：号码按来时的样子保存；同一个号码归到同一个 peer；读号码只为了显示归属地，从不改写它。

保存：按来时的样子，只去掉分隔符

  • 用户输入的、网络送来的号码，保留数字、开头的 +、USSD 里的 * 和 #；去掉空格、横线、点、括号。
  • 什么都不添加：不加国家码，不加区号。设备自己的号码（SIM 上读到的、用户填的）也一样。
  • 一个数字都没有的值（anonymous、隐藏号码）不是号码，存成 ""。短信发件人例外：它可以是名字（EXAMPLECO），按来时的样子保存（去掉首尾空白），自成一个会话，只按字符串精确匹配，不和任何号码合并。
  • Message.peer、Conversation.peer、CallRecord.peer、Voicemail.peer、Call.number、联系人的 numbers、ownNumber 都是保存形式。
  • POST /v1/call/dial 的 number、POST /v1/messages 的 to 先去掉分隔符再校验，按输入的样子交给模块。

一个人，一个会话

记录新的短信或通话时，先看已有的 peer（短信和通话记录里的）有没有和它是同一个号码的——按联系人列表里的匹配规则（只比数字，相同或一个是另一个至少 7 位的尾部）。有完全相同的就用它；否则用最近活跃的那个匹配项；都没有才用这个号码本身。所以网络送来的 +8613800138000 和用户输入的 13800138000 落在同一个会话里。会话按 peer 字符串分组，路径里的 {peer} 按字符串精确匹配，App 传回来的就是你给它的 peer。

读：只为了归属地

读一个号码只是判断它是哪一类、完整号码是什么，用来查归属地（place、carrier，有 places 时）。保存的号码不因此改变。

规则跟着网络和人写号码的习惯走：从国外打来的电话，以及 SIM 漫游时的每一通来电，都带着 + 或 00 和国家码（3GPP TS 23.081 §1.2.1）；只有 SIM 归属国家或地区的来电按国内写法到达，只有 SIM 本地的固话不带区号；用户知道自己的 SIM 是哪里的，写号码也一样。所以号码里没有的国家码、区号从不假设（SIM 本地固话这一种情况除外）。传坏的来电号码和笔误不在考虑之内。

写法怎么读结果
+ 或 00 加国家码在那个国家或地区里读（有些网络把国际来电送成 0085261234567）；国家码后面多打的长途 0 不算（+86 (0)571 2345 6789 读作 +8657123456789，保存为 +86057123456789）。那个国家或地区发放的号码：国际。那个国家或地区的热线：服务号，按它的规则读和分组（+86 400 123 4567、+1 800-555-0199，归属地是那个国家或地区）。其他：未解析。
三到六位数字，或 USSD短号（110、10086、*100#）。服务号
其他一切只在 SIM 的归属国家或地区（device.home.country）里读，依次：完整的国内号码（手机号、带区号的固话，区号带不带长途 0 都行：13800138000、057123456789、57123456789）；这个国家或地区的热线（4001234567）；中国卡上 106 后跟 5–17 位是短信网关号（杭州卡上的 10690000 是网关号，不是本地固话）；加上 device.home.areaCode 就是固话、且不以长途前缀开头的——SIM 本地的固话（杭州卡上的 23456789 读作 +8657123456789，有归属地，保存的仍是 23456789）。国际 / 服务号 / 网关；都不是就未解析，包括没写 + 或 00 的国家码（8613001300000），以及不知道 SIM 归属时的一切。

设备在哪里、手机自己的地区，都不起作用。国际号码和服务号有归属地（热线按它自己的国家或地区查）；网关和未解析的没有，不去猜。判断一个国家或地区发放哪些号码、怎样分组，用 libphonenumber 的表（+1 号码归发放它的地区，如加拿大，分组用美国的写法）。完整的用例表（保存成什么、读成什么、怎么显示、归属地）在 本仓库的 fixtures/number-rules.json，可以拿来测你的实现。

App 怎么显示。 它只按号码所属国家或地区的写法给保存的数字分组：国内写法仍是国内写法（区号少打了 0 就不显示 0：571 2345 6789），+ 仍是国际写法，00 加国家码显示成 +（0085261234567 → +852 6123 4567，保存和拨出仍是原样）；国家码后面的长途 0 不显示（+61 412 345 678）；本地固话按完整号码分组、但不显示区号（23456789 → 2345 6789）；短号、网关和未解析的号码显示成一串数字。所以你不需要、也不应该替用户“补全”号码。

兼容承诺

我们打算让 API 第 1 版只增不改，按设计，App 升级不会让已经接好的后端失效。具体是：

  • 写下的东西不会删除、不会改变含义，字段不会换类型。
  • 新东西只以新的可选字段、新的事件类型、或新的可声明特性出现。你没实现的，App 都有退路。
  • 双方都忽略不认识的字段、事件和特性，谁都不能因为新东西而出错。
  • 错误 code 稳定；遇到不认识的 code 按 HTTP 状态处理。
  • 做不到这些的改动会是第 2 版，有自己的 /v2，App 会继续用 v1 和你对话。

其他须知

  • 码的有效期。 短码要短时有效、用一次作废。参考后端：六位数字，5 分钟有效，同一时间只有一个有效的码（生成新码时旧码作废），配对成功立刻作废；比较前去掉码里的非数字字符（"482 913" 也算对）。你的“码”本身就是长密钥的话，可以直接把它当 token 返回。
  • 限速。 失败按来源地址计数，不能让人靠试猜出码。参考后端的做法（次数和时长是推荐值）：
    • 算失败的：错的配对码，以及不认识的 token（每个不同的值只算一次，同一个值重复提交不再加）。没带任何凭据的请求、已撤销的 token（回 410）不算。
    • 同一地址 10 分钟内 5 次失败就封 15 分钟。这个地址有一次鉴权成功（任何手机的有效 token），就清零它的失败计数。
    • 封禁期间只拒绝又一次猜测：不认识的 token、错的配对码、错的网页入口码回 429，且不再计数。能用的 token、正确的配对码照常通过；已撤销的 token 仍回 410。
    • 每个 429 都带 Retry-After（包括事件流升级被拒时），即封禁还剩的秒数。
    封禁按来源地址算，但永远不会挡住有效的 token，所以经同一个代理或隧道连进来的手机不会被一起封掉。
  • 同一个 uid 再次配对：沿用原来的客户端 id，换新 token，旧 token 从此回 401（它已不是你认识的 token），用旧 token 开着的事件流连接要关闭。uid 是 36 位的 UUID 字符串；格式不对就当作没带，按新手机配对。
  • code 缺失或不是字符串回 400（details.field: "code"）：这不算一次失败尝试，也不消耗码。
  • name 去掉首尾空白、截到 60 个字符，空的或不是字符串就用 "iPhone"。lang 是以 zh 开头的字符串为 zh，否则为 en。
  • endpoints 填什么。 App 配对后只用这张列表连你（列表为空时才退回配对时用的地址），所以里面至少要有一条手机能连上的。填长期有效的地址：局域网用 Bonjour 主机名（http://my-mac.local:9400），不要填会变的 DHCP 地址。label 显示在 App 设置页，按这台手机的 lang 写（参考后端：zh 为 本地网络，en 为 Local network）。每次返回端点列表（这里、GET /v1/client、client 事件）都按读者语言生成。
  • 只存 token 的哈希。丢了就重新配对。
  • 可以只在部分地址上接受配对：参考后端只在局域网接受 POST /v1/pair，不接受来自公网的配对。
  • 让 App 找到你：局域网里用 Bonjour 发布 _cellpilot._tcp（TXT 记录 api=1、path=/）。不发布也行，用户可以直接输入地址。

端点与远程连接

一个端点就是一条路：地址，加上穿过这条路上的代理或隧道所需要的东西。可以同时给几条：App 按优先级经有响应的最优那条连接——比当前更优的会持续尝试打开事件流，一通就换上去；更差的保持关闭，直到当前这条断掉。列表变了就发 client 事件，App 按需重连。

字段作用
id · label必需标识和显示名，显示在 App 设置页。
url必需基础地址，不含 /v1（App 在它后面接 /v1/…）。
priority必需越小越优先。App 用最优先的那条能连上的，好的恢复时自动换回去。
headers可选经这条路的每个请求和事件流都带上：隧道的服务令牌、代理的凭据。
tokenHeader可选代理自己要用 Authorization 时填 "X-CellPilot-Token"，App 就把 token 放在这个头里。
tlsPin可选服务端证书（DER）的 SHA-256，base64（十六进制带不带冒号也行）。App 对这个端点只信任这张证书，不论谁签发的，别的一律拒绝。用于自签名证书。
clientCertificate可选服务端要求客户端证书（双向 TLS）时 App 出示的证书：{ "p12": "<base64>", "password": "…" }。
vpn可选要先开哪个 VPN 才能连上，比如 "Tailscale"。连不上时 App 会提示用户打开它。这里的“VPN”指连回你自己家庭网络的私有网络，不是用来访问你所在地被屏蔽网站的服务；请遵守你所在地关于网络接入的法律法规。

不论哪种方式，都要能穿过这两样

  • WebSocket。 事件流要一直连着，App 才能实时收到短信和来电。代理要放行升级（Upgrade、Connection 头），空闲超时不低于 30 秒，你的后端每 10 秒 ping 一次。
  • token。 默认在 Authorization: Bearer，端点有 tokenHeader 时在 X-CellPilot-Token。

    "p12": "MIIK…",
    "password": "…"
  }
}
  • tlsPin：服务端证书的指纹，App 只认这一张。不要求客户端证书时去掉 clientCertificate。
  • clientCertificate：代理要求的客户端证书，p12 是证书包的 base64。证书是正规签发的就去掉 tlsPin。

算证书指纹、做客户端证书包

终端
# tlsPin：服务端证书 DER 的 SHA-256，base64
openssl x509 -in server.crt -outform der | openssl dgst -sha256 -binary | base64

# clientCertificate.p12：客户端证书和私钥打成带密码的 PKCS#12，再转 base64
openssl pkcs12 -export -inkey client.key -in client.crt -out client.p12 -passout pass:你的密码
base64 -i client.p12

证书换了，tlsPin 也要跟着换；这是端点列表的变化，按规则发 client 事件。

配对用的地址。 配对用的是用户输入的地址，端点的 headers、tlsPin、clientCertificate 要等配对的响应里才有，所以配对地址要不靠它们也能连上。参考后端只在局域网接受配对，不接受来自公网的配对；配对后 App 只用端点列表。

通话记录

打过、接过、没接到的电话。

通话记录怎么写

每通电话一条记录，由你在通话的三个时刻写。Call.id 就是这条记录的 id。

时刻你写什么
开始：来电开始响铃，或拨号被模块接受新建记录：outcome: "in-progress"，startedAt 为此刻，answeredAt、endedAt、durationS 为 null。
接通outcome: "answered"，answeredAt 为此刻。你的答录机替用户接起时改写 "voicemail"。
结束写 endedAt；接通过的写 durationS（接通到结束的秒数，四舍五入到整秒；答录机接的从它接起算，被手机接过去后也是，answeredAt 仍是答录机接起的时刻）；按下表写最终的 outcome。然后发 call 事件（call: null）和 calls 事件。
outcome含义什么时候写
in-progress还没接通开始时。
answered接通了，还在通话接通时。结束时一定换成别的值。
completed接通过，已结束结束时，只要接通过（不论谁挂断）。
voicemail你的答录机接了并留下了留言答录机接起时，结束时留下了留言就保持（没有留言改为 missed，见答录机怎么工作）。用户从答录机手里接过去的，改为 answered，结束时为 completed。
missed来电，一直没接通结束时：对方挂了、用户拒接（hangup）、没人接，都算；答录机接了但没有留言的也算（answeredAt、durationS 为 null）。同时把 seen 设为 false。
busy去电，对方忙结束时，模块报对方忙。分辨不出的后端写 failed。
no-answer去电，对方没接结束时，模块报无人接听。分辨不出的后端写 failed。
failed去电没接通，其他原因结束时：用户在接通前挂断、网络拒绝、模块分不清原因，都写它；知道网络原因就填 endReason。
rejected来电被拒接可选。参考后端不写它，拒接记为 missed；你要区分拒接也可以写，App 显示“已拒接”。
  • App 的显示：answered 和 completed 都显示“已接听”，missed 和 voicemail 都算未接，in-progress 显示“进行中”。
  • 记录建立和接通时不发 calls 事件，这期间 App 从 call 事件知道通话的状态。calls 在记录结束、被看过、被删除、联系人改名时发（手机从答录机手里接过通话时也发，记录变为 answered）。
  • seen：只有未接来电（包括答录机接了但没有留言的）结束时为 false，直到有人打开；其他记录一开始就是 true——去电、接通的，以及有留言的答录（它靠留言的 heard 计入角标）。
  • 后端重启（或模块断开）时还没结束的记录，那一刻收尾：没接通的（in-progress）改为 failed；answered 改为 completed，durationS 算到那一刻；voicemail 如果答录机留下了留言就保持不变，没有留言则改为 missed（answeredAt、durationS 为 null）——被重启打断的录音会丢失。都写上 endedAt。
  • 隐藏号码：Call.number 为 null，通话记录和留言的 peer 为空字符串 ""，推送里的来电者写“无来电显示”。来电刚响时可能还不知道号码，号码到了就填进 Call.number 和记录的 peer，并发 call 事件。

GET/v1/conversations

按号码分组的会话，按最后一条短信的 id 新的在前。App 的短信首页。

参数讲解

请求参数

没有。

响应

200，JSON

字段类型说明
conversationsConversation[]会话。

例子

响应
{
  "conversations": [
    {
      "peer": "+8613812345678",
      "lastBody": "晚点到",
      "lastAt": "2026-09-30T08:20:00.000Z",
      "lastDirection": "out",
      "unread": 0
    }
  ]
}

其他须知

  • 每个 peer 一项，按最后一条短信的 id 从大到小排，lastAt 是那条短信的 createdAt；unread 数的是收到且未读的。不分页。
  • 还没收齐的长短信也和别的短信一样算：在会话列表里（目前拼好的正文作为 lastBody）、在搜索里、在未读数和角标里。
  • 列表变化（新消息、已读、删除）时发 conversations 事件。

一个会话的短信

核心
GET/v1/conversations/{peer}/messages

和一个号码的短信，新的在前，可以往前翻页。

参数讲解

请求参数
参数位置类型必需说明
peer路径string必需对方号码，URL 编码（+ 写成 %2B）。
beforeId查询integer可选只要比这条更早的。
limit查询integer可选最多几条，默认 100，最多 500。
响应

200，JSON

字段类型说明
messagesMessage[]这一页的短信。

例子

响应
{
  "messages": [
    {
      "id": 5011,
      "direction": "in",
      "peer": "+8613812345678",
      "body": "快递已放前台",
      "status": "received",
      "createdAt": "2026-09-30T08:19:00.000Z",
      "deviceTime": "2026-09-30T08:18:57.000Z",
      "parts": null,
      "error": null,
      "read": false
    }
  ]
}

其他须知

  • 长短信：从第一段起就是一条记录。每收到一段发一次 message 事件——同一个 id，body 是目前拼好的，parts 为 { received, total }；最后一段之后才发 conversations 并推送，到这时才通知。收齐后 parts 仍留在记录上；只有一段的短信 parts 为 null。每段都可能让角标变化（发 badge 事件）。
  • 只看 peer 字符串完全相同的短信（见号码与会话）。没有这个号码的短信时回 200 和空列表，不回 404。
  • limit 超出 1–500 时夹到范围内，不报错；beforeId 不是数字时当作没带。

发送短信

核心
POST/v1/messages

用 SIM 发一条短信。

参数讲解

请求参数
参数位置类型必需说明
to请求体string必需对方号码，用户输入的样子：去掉分隔符后为 3–20 位数字，可带开头的 +。
text请求体string必需正文，不能为空字符串。没有长度上限，太长时由你分段发送。
响应

200，JSON；格式不对 400，没接模块 503

字段类型说明
messageMessage刚记录的这条短信，direction 为 out，read 为 true，status 一般为 pending。

例子

请求
{ "to": "+8613812345678", "text": "晚点到" }
响应
{
  "message": {
    "id": 5012,
    "direction": "out",
    "peer": "+8613812345678",
    "body": "晚点到",
    "status": "pending",
    "createdAt": "2026-09-30T08:20:00.000Z",
    "deviceTime": null,
    "parts": null,
    "error": null,
    "read": true
  }
}

其他须知

  • 响应是 { "message": { … } }，短信放在 message 键下。
  • 校验：to 不对回 400（details.field: "to"），text 为空或不是字符串回 400（"text"）；没接模块回 503，这时不记录。
  • 事件的顺序：记下短信时发一次 message 事件（status: "pending"）；发出或失败后再发一次 message 事件（sent 或 failed，失败时带 error），紧接着发 conversations 事件。
  • 可以记下就回 pending，也可以等发送结束再回（这时 status 已是 sent 或 failed），App 两种都接受。参考后端是等发送结束才回。
  • 交给模块时照用户输入的 to（去掉分隔符）发；记到哪个 peer 下见号码与会话。
  • 后端重启或模块断开时还没发完的短信，改为 failed 并写上 error。

留言与转写

特性 voicemail 和 transcription：你的答录机替用户接电话。

答录机怎么工作

有 voicemail 特性时，你的答录机可以替用户接电话、录下留言。这一节讲一通被答录机接的电话从头到尾发生什么。

阶段你做什么App 看到的
接起两种情况：来电响铃 settings.voicemail.answerAfterS 秒没人接（reason: "no-answer"，开关关掉时不接）；或用户按了拒接、App 调用 POST /v1/call/screen（reason: "declined"）。只有通话音频在流动时才接起；音频通路没能启动时直接挂断，这通电话算未接。你接起电话，通话记录写 outcome: "voicemail"。call 事件：state: "active"，holder: null（没有哪台手机在通话）。
开始录音发 voicemail 事件：recording: true、transcript: ""。App 显示“答录机正在接听”。
录音中有转写时，每识别出一段发一次 voicemail 事件：transcript 是到目前为止的全文，delta 是这次新增的部分。没有转写就不发。实时显示对方在说什么。
结束对方挂断、录满 maxSeconds 秒（你挂断）、或用户接过（见下）。发 voicemail 事件：recording: false，transcript 为最终全文（事件里没有转写为 ""，从不为 null；保存下来的留言什么都没转写出来时 transcript 为 null）。录音中通话结束时（对方挂断或录满），先发 call（null）和 calls，再发这个 voicemail 事件，然后才是 voicemails。录音过程中通话音频故障，录音就在那里结束：保留之前录到的部分，然后挂断。录音含有留言内容（有高于线路本底噪声的声音，或者有转写时转写出了文字）才保存为一条留言，发 voicemails 事件并推送 voicemail 通知。其他情况——不满 1 秒，或者不论多长都是静音——都不算留言：录音一点不保留，通话记录按未接结束（outcome: "missed"，answeredAt、durationS 为 null，seen: false），推 missed-call 通知（“未接来电 · 未留言”）。留言出现在列表里。
voicemail 事件
{ "type": "voicemail", "recording": true, "peer": "+8613812345678", "reason": "no-answer", "transcript": "" }
{ "type": "voicemail", "recording": true, "peer": "+8613812345678", "reason": "no-answer", "transcript": "你好，我是物业的", "delta": "我是物业的" }
{ "type": "voicemail", "recording": false, "peer": "+8613812345678", "reason": "no-answer", "transcript": "你好，我是物业的，明天停水。" }
  • 接过来：答录机在接时，手机调用 POST /v1/call/claim 或 POST /v1/call/answer。你停止录音，电话不挂，这台手机成为持有者，声音接到它上面。事件依次是 call（新的持有者）、calls（记录改为 answered），然后才是答录机的 voicemail（recording: false）。通话结束时记录为 completed（并发 calls 事件），answeredAt 仍是答录机接起的时刻，durationS 从那时算；已录的部分含有留言内容时照样保存为一条留言，但不推 voicemail 或 missed-call 通知——用户正在通话。
  • peer 是来电号码（保存形式），隐藏号码时为 ""。
  • 答录机的开关只决定会不会去接；voicemail 特性在开关关掉时照样声明，见特性一览。
  • 录音与同意：对来电者录音、转写录音并让用户实时收听，视来电者和用户所在地的法律，可能需要告知来电者或取得其同意。后端应当播放问候语，说明来电由答录机接听并会被录音。遵守当地法律是后端运行者的责任。录音和转写保存在后端上。

    收到短信、发出短信被记下或状态变化message

音频帧

通话声音走事件流的 WebSocket 二进制帧，双向，只在持有者和你之间传。每帧 323 字节：3 字节帧头，加 20 毫秒的声音。

字节偏移长度内容
01方向：0x01 下行（你 → App），0x02 上行（App → 你）
11序号高 8 位
21序号低 8 位（序号是 16 位大端整数）
3320PCM：16 位有符号小端、8 kHz、单声道，160 个采样 = 20 毫秒
一帧的样子（十六进制）
01 00 2A  F4 FF 02 00 1C 00 … （共 320 字节 PCM）
│  └──┴── 序号 0x002A = 42
└──────── 0x01：下行
  • 序号：16 位，每发一帧加 1，到 65535 后回到 0；两个方向各自计数。收到的一方用 16 位序号算术比较：d = (seq − last) mod 65536，last 是最近播放的那帧的序号。d == 0 是重复，d > 32768 表示这一帧比 last 旧，都丢掉；1 ≤ d ≤ 32768 是新帧，播放并令 last = seq。
  • 只和持有者交换：下行只发给持有者的连接（一台手机经几个端点连着时，每条连接都发同一帧、同一个序号，App 只播一次）；上行只收持有者发来的，其他的一律丢掉。
  • 节奏：下行随声音到来发，每 20 毫秒一帧，不成批发；App 也按采集的节奏发上行，每 20 毫秒一帧。没有编解码器，就是裸 PCM。
  • 静音的上行帧不代表什么；同一台手机有几条连接时，你可以按声音电平判断哪条是活的。
  • 什么时候开始传：见事件流里的 audio 事件。没有声音通路的后端不传音频帧，status.audio.ready 为 false。

推送

特性 push：App 不在前台时，只有 Apple 的推送能叫醒它。你把推送内容加密好交给 CellPilot 中转，中转转给 Apple。这一组是你要实现的接口和推送的格式；中转那边的接口在下一组。

推送全流程

推送的材料分在几处，这一节把它们串起来。先做一次性的准备，之后每件事按“先问在线的 App，再决定推不推”处理。

准备（每台手机一次）

  1. App 登记推送 token：POST /v1/client/push-tokens（普通通知 alert，来电 voip）。
  2. App 读 GET /v1/push，看到 mode: "none" 就向中转要一张一次性许可，交给你：POST /v1/push/enrol。
  3. 你用许可去中转登记自己的公钥：POST /v1/daemons，记下 daemonId。之后每条推送都用私钥签名，见中转请求的签名。

来了一通电话

  1. 开始响铃。 建通话记录（in-progress），给所有连接发 call 事件（state: "incoming"，holder: null）。
  2. 知道号码后（或响铃 2 秒还没有号码，就当隐藏号码）通知每台手机： 有 VoIP token 的，立即发 VoIP 来电推送，并记下发给了谁；没有 VoIP token 的，先问（notify，kind: "call"，等 1.5 秒），回 foreground 就不推，否则推一条 call 类的普通通知。
  3. 不响了（某台手机接了、某台手机拒接、对方挂了、答录机接了）：收起收到过 VoIP 来电推送的手机上的系统来电界面，规则见来电结束的规则。
  4. 通话结束。 写最终的 outcome，发 call（null）和 calls 事件（答录机录音中结束的，之后才发 recording: false 的 voicemail 事件）。是 missed 的：发 badge 事件，再对每台手机问 notify（kind: "missed"，等 5 秒），没回 foreground 的推 missed-call 通知。
  5. 答录机录完。 发 voicemails 事件，再按同样的方式通知 kind: "voicemail"，推 voicemail 通知（录音没有留言内容就不建留言，改推 missed-call，正文“未接来电 · 未留言”）。

来了一条短信

  1. 记下来，发 message 和 conversations 事件。长短信每收到一段发一次 message，收齐后才继续下面几步。
  2. 发 badge 事件，再对每台手机问 notify（kind: "sms"，id: "sms-<id>"，等 5 秒）。回 foreground 的不推；其他的推一条 sms 通知，带当前角标。
  3. 之后用户在手机 A 上读了：conversations 事件；角标变了，给连着的手机发 badge 事件，给没连着的推一条只含角标的推送（300 毫秒内的变化只发一次，事件和推送都是）。

没有 notify 特性时跳过“问”，直接推。每件事发什么的总表见每件事发什么。细节分别在：notify 与 ack（问答的格式）、推送内容（每种推送长什么样）、推送加密、推送分流（推给谁、怎么省额度）、经中转推送和中转的回答。

密钥
key = HKDF-SHA256(ikm = SHA-256(token), salt = "cellpilot", info = "push-v1", length = 32)

  • mutable-content: 1 必须有：App 的通知扩展靠它在显示前解开 e、换上真正的标题和正文。
  • badge：除来电那条之外，每条普通通知都带当前角标（算法见下）。

明文里能写什么

  • 中转只转发加密的推送。普通通知必须正好有 aps、e、v 三个键；aps.alert.title 必须是 "CellPilot"，aps.alert.body 是不超过 40 个字符的字符串；aps 里只能有 alert、sound、category、interruption-level、mutable-content、thread-id、badge（0–99999 的整数）；e 长度 16–4000。不符合的回 400。
  • 明文的 body 是解不开时手机上显示的那句话，具体措辞由你决定，但后端必须让明文保持通用，不要放内容。参考后端按手机语言用这几句：

来电结束的规则

这是唯一完整写明的地方，其他几处都链接到这里。

  • 什么时候：来电从 incoming 变成别的状态（接通、或结束）的那一刻。
  • reason：接通了且接的是某台手机 → answered；接通了但接的是你的答录机（包括用户按 screen 交给答录机）→ unanswered；没接通就结束、且 15 秒内有手机调用过 POST /v1/call/hangup → declined；其他（对方挂断、无人接）→ unanswered。
  • 发给谁：每台收到过这通电话 VoIP 来电推送的手机，除了接听的那台、拒接的那台（15 秒内调用过 hangup）、按 screen 交给答录机的那台（同样在这 15 秒内）——它们自己已经知道不响了。没收到过 VoIP 来电推送的手机不在其列。
  • 怎么发：先对它发 notify（kind: "call-end"，id: "call-<callId>"，带 callId、reason），等 1.5 秒。回了 ack（foreground 或 background 都算）说明它已经自己收起来电界面，不推；没回、或没连着，就发上面这条 VoIP 结束推送。
  • 提前确认的：系统根本没显示这通来电的手机（被专注模式拦下），可能不等你问就先发来 ack（kind: "call-end"，id: "call-<callId>"）。记下它；响铃结束时既不问它也不推它。结束推送到了手机还得再上报一次来电，而开启“重复来电”时（默认开启），专注模式会放行同一号码的第二次来电，手机就会闪一下来电界面。

只改角标

只改角标的推送
{ "aps": { "badge": 3 } }
  • 唯一不加密的推送，类型是 alert，只能有 aps.badge 一个键，不带 collapseId。
  • 角标的算法（所有手机相同）：收到的、未读的、不在回收站的短信数 + seen 为 false 的通话记录数 + heard 为 false 的留言数 + 未确认的告警数。没有的特性那一项就是 0。同一个数用在 hello 和 badge 事件、快照的 badge、普通通知的 aps.badge 上。
  • 300 毫秒内的变化只发一次（badge 事件也一样），而且只在这个数和上次发出的不同时才发：整个后端只有一个“上次”，发给任何手机的任何推送或 badge 事件都会更新它，后端启动时以当时的数为起点。

推送分流

中转真正发给 Apple 的每一条推送都计入用户账号的小时和日额度——普通推送、来电推送、只改角标的推送都是；被中转拒绝的不计。推给已经看到的手机，就是白白花掉用户的额度。限额、配额及其计算方式由中转设定，可能会变化；示例中的数值仅作说明。

每台手机单独判断

  1. 有没有活着的事件流连接？ 没有：直接推送。“活着”指这条 WebSocket 在按时回应 ping。
  2. 有连接：先问。 发 notify，等 ack。回 foreground 就不推；回 background 或在时限内没回（来电 1.5 秒，其他 5 秒）就推送。需要 notify 特性。
  3. 只推给这台。 推送时只用这台手机登记的 token，不要一次推给用户所有的手机。

“问”发给每一台已配对、此刻有活着连接的手机，不管它有没有登记推送 token；没有 token 的手机回 background 或没回时，就没有可推的，什么都不做。

别的省额度的做法

  • 每条推送都带 collapseId，和 notify 的 id 相同（sms-<id>、call-<id>、alert-<id>）。
  • 除来电那条之外，每条普通推送都带上当前的 aps.badge，多数时候不需要再单独发角标推送。
  • 中转回 410 时删掉这个 token；手机解除配对时删掉它所有的 token。
  • 没有定时重试：每件该推的事照常推一次，被拒了就等下一件事（见推送状态）。

test-relay.mjs：中转替身

不用真中转和 Apple 就能测你的推送。它检查中转检查的东西——登记证明、每个签名、时钟、nonce、推送是否封好——用给它的客户端 token 打开每个封好的载荷，让你看到手机会收到什么；中转会放行、但 App 依赖的东西不对时（类别、collapse id、声音、中断级别、封装的字段），那一行日志带 warnings。每个请求在标准输出打一行 JSON。

把你后端的中转地址指向它（测试用的覆盖设置：POST /v1/push/enrol 本身只接受 https），再从 App 或直接用 POST /v1/push/enrol 登记，许可是任意 16–200 个字符；许可 expired-grant-for-testing 总是被拒，和过期的一样。--state <文件> 把登记过的后端存进文件，替身重启后不用重新登记。

终端
node tools/test-relay.mjs --port 18780 --state relay-state.json [--client-token <token>]…
curl -X POST http://127.0.0.1:18780/_tokens -d '{"token":"<客户端 token>"}'        # 配对之后再加 token
curl -X POST http://127.0.0.1:18780/_next -d '{"answer":"quota","times":3}'         # 接下来三条推送
curl -X POST http://127.0.0.1:18780/_next -d '{"on":"enrol","answer":"grant"}'      # 下一次登记
curl -X POST http://127.0.0.1:18780/_next -d '{"answer":"ok"}'                      # 恢复正常
_next 的回答取值
推送（默认，"on": "push"）not-enrolled（401）、suspended / not-entitled（402）、unbound（403）、quota / rate（429）、gone（410）、apns（502）、unreachable（500）
登记（"on": "enrol"）grant / proof（401）、rate（429）、unreachable（500）
恢复正常ok

times 是接下来几次用这个回答，默认 1。用它看你的后端怎样把这些回答写进 problem、怎样处理 gone 和 not-enrolled。

常见问题

我的后端不在局域网，App 怎么连？

在端点列表里给一条远程的路，见端点与远程连接。App 按优先级用能连上的最优那条，更优的通了就换上去。

一定要做 snapshot 吗？

不用。没有它 App 每次连上逐个列表读一遍，结果一样正确。做了之后，没变化时一个请求都不发，适合移动网络。

没有 Apple 开发者账号能收推送吗？

能。推送经 CellPilot 中转，你不需要 Apple 开发者账号。你要实现 push 特性；用户在 App 里用 Apple 登录后，App 替你在中转登记。

来电时手机没响？

来电要用 VoIP 推送才能调起系统来电界面：检查你是否收到了 kind: "voip" 的 token，经中转推送时 type 是否为 "voip"，推送体是否只有 e 和 v，加密内容里是否有 callId 和 number（见推送内容）。过期时间、主题这些由中转设置，你不用管。用户关掉了系统来电界面时 App 会撤回 VoIP token，这时改发 call 类普通通知。test-relay.mjs 能打开封好的载荷，让你看到手机会收到什么。
